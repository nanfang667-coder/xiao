# 合作网站图片获取

入口：后台首页 → 合作网站图片（/adminzhangzhang/partner-import）。仅管理员可使用。

## 使用

1. 添加新来源时展开“合作网站来源配置”，填写名称和 HTTPS 网站根地址。编辑已有来源时，在上方选择来源后点击旁边的“编辑此来源配置”；下方会自动展开配置并选中同一个网站，采集规则 JSON 和保存按钮直接可见。已有来源配置可以继续使用，编辑后仍需点击“保存来源配置”才会生效，不会自动修改或保存。
2. 选择来源和获取方式，粘贴完整 HTTPS 网址，再点击“开始获取”：
   - 当前列表页：只处理输入的这一页，最多 50 篇，不自动翻页。
   - 前3页：填写所需分类的第一页网址，逐页处理第1、2、3页，每页最多 50 篇。没有下一页时按实际页数结束；翻页地址含糊、不安全或重复时停止并提示，不把未读取的页面算作完成。
   - 单篇文章：只处理输入文章的图片。
3. 图片逐篇显示，可单张下载，也可点击“下载全部图片（ZIP）”。全部图片直接放在压缩包同一层，不建立子文件夹；按 page-001-photo-01.jpg 这样的唯一名称区分。
4. 每批最多 400 张图片或 64 MB，达到任一上限会暂停。先点击“下载本批图片（ZIP）”，确认文件已保存后再点击“已保存本批，继续获取”；确认前可重复下载，确认继续后会清空本批预览。任务保留文章进度和去重记录，不用重新输入网址。相同图片按转码后内容哈希去重，跨列表页和跨批次都不会重复收入。
5. 可暂停并继续；切换标签页或离开页面会停止后续请求，正在进行的一篇可能仍会完成。前3页模式每次只读取一张列表页，不会在服务端一次悄悄抓取全部页面。
6. 图片和未完成任务仅保留在当前浏览器页面内存中。刷新、离开、清空或开始新任务都会清除预览、进度和去重记录，请及时下载。暂停进度不能跨刷新恢复；开始新任务后会重新去重。

来源配置通常只需保存一次。若图片在另一个域名上，在高级配置中逐行填写完整 HTTPS 图片 origin，最多 10 个。只允许明确配置的图片来源，重定向不能绕过域名限制。

## 获取规则

默认列表规则支持标题中包含链接，也支持链接包住 h2、h3、h4 标题的卡片，不限定详情页必须使用本项目的路径。已保存的旧默认链接规则会在读取时自动升级；自定义选择器保持原样。

Discuz 论坛列表也使用默认规则：识别明确的 `forum.php?mod=forumdisplay&fid=...` 或 `forum-...html` 列表上下文，支持标准帖列表标题、原有标题卡片及只含封面图的自定义图片卡片。图片卡片必须同时指向严格的 `forum.php?mod=viewthread&tid=...` 或 `thread-...html` 帖子地址，有可用的非头像图片，并且不在导航、广告或操作区。唯一的标准 `form#moderate` 允许作为帖列表容器，但其中的操作按钮、头像和广告仍被排除；普通表单、密码或挑战表单不适用此例外。普通的同路径查询、分页和会员链接不会因此变为帖子链接。同帖多页链接归一为首帖首页并去重；图片只从能明确识别的首帖正文及其同一内容区内的附件中获取，不回退到回复、签名或头像。附件区须归属于该首帖及唯一正文；支持标准附件的懒加载地址，不执行目标网页脚本。

如果这个来源此前保存了自定义帖子链接规则，请点击“编辑此来源配置”→“恢复默认帖子链接规则”→“保存来源配置”，然后回到上方重新点击“开始获取”。自定义图片选择器仍有优先权；若之前配置了不适用于该站的图片选择器，应先删除该项再保存。标准 `.pg` 分页区中明确标为下一页的 `a.nxt` 可在前三页模式下继续；实际需要登录、脚本渲染或无法确认首帖的非标准主题仍需另外适配。

若列表已识别但每篇均为 0 张，且论坛主题将整个帖子区初始设为隐藏，可点击“编辑此来源配置”→“应用 Discuz 首帖图片规则”→“保存来源配置”，再重新“开始获取”。按钮只替换该来源的图片规则，保留列表、翻页、域名和其他设置，不自动保存。此固定预设沿用首帖身份验证和附件归属检查，仅允许唯一 `div#postlist` 的 inline `display:none`；其他隐藏祖先、隐藏图片、语义隐藏、密码/挑战区仍被排除。它不会执行网站脚本，也不会对所有来源放开隐藏过滤。默认规则仍拒绝隐藏的首帖；其他自定义图片选择器仍按管理员配置执行。

2026-10-24 经用户授权，仅对指定论坛的单张公开列表页、指定第一篇公开详情 HTML 及其引用的同站公开脚本作结构统计。首次验证误写了域名中的一个字母，随后已用截图中的准确地址重新验证：21 个图卡全部位于标准帖列表表单内；修正表单误判后，新默认规则匹配 21 个不同帖子链接，识别到下一页且保留了分类、区域等筛选参数。指定详情中的 3 张图片位于首帖正文旁的附件区，整个 `#postlist` 初始有隐藏样式；公开脚本静态分析未确认无条件自动显示机制。应用明确的来源预设后，同一篇仅计数复测从 0 张变为 3 张。诊断未返回标题、正文、联系方式、图片地址或脚本原文，未执行脚本、跟随下一页、读取其他详情或下载图片；实际下载及其余帖仍需用户点击获取验证。

`https://66feng.com/list?city_id=110000` 已有专用公开列表接口适配，选择“列表页”或“前三页”即可使用，不需要修改帖子链接、图片或翻页选择器，也不需要安装浏览器。此来源直接读取列表内的图片数组，不打开帖子详情，不提取或返回标题、正文、联系方式。前三页从所填城市的第1页开始，按照接口返回的页码、每页条数及总条数继续，最多3页；当前列表页保留输入的页码。没有图片的条目会显示无图片结果并继续其他条目。可选 URL 参数 `post_type` 支持保留明确的类型筛选，未填写时使用该列表的默认类型；图片域名仍须属于来源网站或已明确配置的额外图片域名。

出现“帖子链接规则未匹配到元素”时，先在上方选中对应来源，点击“编辑此来源配置”，在展开的配置中点击“恢复默认帖子链接规则”，再保存来源后重试。此按钮只替换帖子链接选择器，保留图片、翻页及其他配置；它不会自动保存。若自定义选择器对该网站已经有效，无需恢复。无真实 href 的脚本点击卡片仍需网站提供可读取的链接或另行适配，不能仅凭此错误推断网站结构。

默认图片提取识别本项目帖子模板、独立文章图片和受支持的静态 Nuxt 文章数据；排除明确头像及作者资料区域。无需填写标题、正文、价格或联系方式，不生成帖子内容。自定义图片选择器可覆盖默认区域判断。

规则示例（虚构选择器）：

```json
{
  "postLinkSelector": "main .post-card a.post-link",
  "photoSelector": "article .photos img"
}
```

在来源的“采集规则（JSON）”中填写。列表选择器匹配 a 元素，图片选择器匹配 img 元素。原有 fields 配置为兼容旧来源保留，图片获取忽略这些文字字段。

### 前3页的翻页配置

默认识别公开 HTML 中的 `rel="next"` 链接，以及分页区域里明确标为“下一页”或“Next”的链接。特殊网站只需配置一次，以后选择该来源并填写第一页网址即可。找不到下一页就结束当前已读取页；需要指定翻页方式时，可使用以下一种规则。

下一页链接选择器示例：

```json
{
  "postLinkSelector": "main .post-card a.post-link",
  "photoSelector": "article .photos img",
  "nextPageSelector": "nav.pagination a.next"
}
```

`nextPageSelector` 必须匹配指向下一页的 a 元素。多个元素指向同一个下一页可以去重，指向不同页面会停止并提示；不要选中所有页码链接。

分页地址模板示例：

```json
{
  "postLinkSelector": "main .post-card a.post-link",
  "photoSelector": "article .photos img",
  "pageUrlTemplate": "/category/piano?region=guangdong&page={page}"
}
```

模板只能含一个字面量 `{page}`，依次替换为 1、2、3。可以填写与来源同源的完整 HTTPS 地址，也可使用相对路径（如上例或 `?page={page}`）；不能跨域、带账号密码、使用 HTTP 或指向非标准端口。若同时配置模板和下一页选择器，模板优先。

建议使用以 `/` 开头的路径或完整 HTTPS 地址。裸相对模板（如 `pages/{page}`）统一相对来源网站根目录解析，不随当前分页路径累加；仅查询参数模板（如 `?page={page}`）保留当前页面的路径。

**配置模板后，前3页模式从模板生成的第1页开始，不会保留输入网址中的任意分类或筛选参数。** 模板必须写全所需分类和筛选条件；例如上例固定处理钢琴分类、广东地区。未配置模板时，则从输入的第一页网址开始，沿明确的下一页链接继续。当前列表页和单篇文章模式始终使用输入网址，不套用翻页模板。

支持公开的服务端 HTML、受支持的静态数据和上述已适配的公开列表接口，不执行目标网站 JavaScript，不接收账号或 Cookie。未知动态网站仍需专用适配，不能通过修改选择器读取空 HTML。没有找到图片时，检查页面类型、图片选择器和额外图片域名；需要登录的数据应由合作方提供导出。

每篇最多 8 张图片，输入及转码输出均限制单张 5 MB、合计 12 MB。只接受 JPEG、PNG、WebP，安全解码后缩放至不超过 1600px 并转为 JPEG，清除原元数据。当前批累计最多 400 张或 64 MB；达到上限时下载当前批后继续。前3页是最多读取3张列表页，不保证有3页有效文章；失败、暂停和未找到的页面会按实际状态提示。

网页下载仅限精确 HTTPS 来源及公网 IP，固定 DNS 解析地址连接，每次 GET 重定向重新校验。公开列表接口仅使用适配器固定地址和受限 JSON 参数，POST 不跟随重定向；单次 JSON 响应不超过 1.5 MB。单页 HTML 不超过 2 MB，列表读取最多 25 秒，单篇含图片处理最多 60 秒。下载失败只显示固定安全提示，不回显响应正文或内部异常。接口取得的图片地址只在当前页面内存中随队列保留；下载动作先验证管理员身份，再重新校验所选来源、图片域名和全部图片地址，空图片数组不会回退读取详情页。

## 已删除的旧流程

原导入任务、待审稿、团队分配、补稿、终审、发布、中转及私有稿件图片入口的页面、接口、界面组件和专用服务代码已从项目删除。旧动作函数不再导出，旧路由不再注册，也不保留“停用”页面或跳转兼容入口。标题、正文和联系方式的导入解析代码一并删除；图片、列表和翻页解析继续使用。

本次删除的是功能代码，不清空数据库历史记录或已有图片，不执行删表迁移。历史导入引用只用于隔离旧稿，防止它们进入普通投稿审核；删除团队账号时仅释放历史记录的可空账号外键。已发布帖子、普通团队投稿、账号管理和固定发帖额度继续使用原流程。来源保存已抽为独立采图配置服务，新采图不写入帖子表或服务端媒体目录。
