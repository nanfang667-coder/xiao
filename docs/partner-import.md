# 合作网站按页导入

入口：后台首页 → 合作网站导入（`/adminzhangzhang/partner-import`）。

## 使用
1. 添加来源名称、HTTPS 根域名。默认识别本项目卡片及标题内的同站帖子链接；详情优先按本项目模板提取，也兼容独立的单篇文章区域；不同结构可在高级配置中填写 CSS 选择器。
2. 首次导入或照片缺失时，先在列表页表单点击“检测图片域名”。程序抽检最多 3 篇详情，列出尚未允许的图片域名；核对后点击“允许这些图片域名并保存”。也可在高级配置中逐行填写 HTTPS origin。检测不下载图片、不创建草稿，保存只更新该来源的图片域名。
3. 选择来源，粘贴某一页列表网址，建立任务。只处理该页列出的帖子，不跟随下一页。
4. 打开任务并点击“开始 / 继续导入”。关闭页面、切换标签或暂停会停止后续下载，已开始的一条可能仍会完成。
5. 在私有待审区逐条审查、编辑文字、选择照片。“保存待审”不发布；明确确认并点击“确认发布”才进入公开帖子表。
6. 不想保留的草稿可在列表中逐条勾选或“全选本页”，点击“删除所选”后核对数量并确认。每批最多 20 条，只能删除待审稿或已拒绝稿；切换页码或状态后重新选择。删除会移除草稿内容和私有照片，不影响已发布帖子，且不能撤销。日后重新导入相同页面时，这些帖子可能再次生成草稿。

任务历史清理：在“导入任务”列表点击某条记录旁的“删除记录”，核对提示后点击“确认删除记录”。此操作仅删除该任务及其进度条目，未完成的条目不再继续；已导入的待审稿、私有照片、已发布帖子及去重记录保留。仍有条目正在处理时会阻止删除，请先在任务页暂停并等待当前条目结束。任务记录删除后不可恢复，如需继续下载剩余内容，可重新建立同页任务。

照片网址覆盖：新导入的草稿默认启用，默认网址来自 SITE_URL（目前 fenglou1.com），参数为底部、居中、宽度 100%、高度 15%。打开待审页后自动加载覆盖预览，不需要先勾选开关或点击预览。设置对本稿保留的照片统一生效，深色不透明区域会遮住该处原内容。所有所选照片加载成功后才能保存或确认发布；若手动修改参数，点击“预览覆盖效果”重新检查。修改参数或选图会清除发布确认。旧待审稿缺少覆盖设置时使用同一默认；明确关闭或已保存的自定义配置会保留，已发布/已拒绝历史不会因缺少配置自动改变。

保存待审仅把覆盖配置存入草稿 JSON；原始私有照片文件不变，待审时关闭覆盖可恢复原图预览。发布时使用与预览相同的服务端处理生成新的公开图片，已发布帖子不会被后台自动修改。预览仍需要管理员登录、校验照片归属且禁止缓存；失败不返回原图冒充覆盖成功。无需数据库迁移。

每页最多 50 帖，每帖最多 8 张 JPEG/PNG/WebP 图片，单图 5MB、合计 12MB。
支持公开的服务端 HTML，不接收账号或 Cookie，不执行网站脚本，也不提取会员隐藏内容。
导入时价格、电话、微信、QQ、其他联系方式一律留空，即使来源规则有这些字段的选择器也不采集。管理员可在待审页手动填写，保存/发布时不会清空手填值；发布前仍需至少一种联系方式。
当默认正文区块缺失时，仅从唯一且标题对应的 article 区域提取正文及其中图片，排除导航、广告、表单、评论及相关推荐；不提取整页 body。多篇文章、空正文或字段歧义会停止导入。显式字段选择器和 data-import 标记优先，不匹配时不会自动换用其他区域。同一文章内的两列表格、明确标签和值结构及有边界的“标签：值”会按字段拆分：服务/服务内容/服务项目→服务内容，年龄→年龄，备注/补充说明→教学案例 / 课程记录；价格、地址和所有联系方式丢弃并留空，颜值及其值继续丢弃。已有显式规则、标记或原模板值优先，缺少的字段分别回填。识别出结构化字段后，唯一文章标题下面、首个字段表格或下个章节之前的介绍段落会进入“教学案例 / 课程记录”，并与明确的表格备注按段落去重合并；显式的课程记录选择器、标记及原模板补充说明仍优先。其他行和无关文字不再混进服务内容；服务为空或缺失、重复字段或嵌套歧义会停止导入。完全没有可识别标签的普通文章保留原正文导入行为。
导入文字会删除独立的“声明信息”标题及其声明正文；普通句子中提及这几个字不会触发清理。结构化声明区块不会提供服务、联系方式等字段，照片提取仍使用原始照片区域。已有待审稿完整刷新网页或重新打开后，编辑框会显示清理后的文字，点击“保存待审”才写回；不需要重新下载。已发布或已拒绝的历史记录不自动改写。
默认图片提取排除明确头像标记和作者资料区域；显式 photoSelector 可人工覆盖头像分类。图片数量大于零不代表已识别到原帖照片，首次使用必须在待审页核对。
对于公开页面内的静态 Nuxt 初始化数据，默认图片提取支持通过当前详情 ID 和唯一文章标题同时绑定的 imageList；仅提取该记录自己的图片 URL，不提取作者、评论、推荐或其他帖子的图片。不会执行 JavaScript，明确图片标记和自定义图片选择器仍优先。
不在公开 HTML 或受支持的静态数据中的内容，需另行接入合作方提供的导出或接口。

## 精简团队分配流程

1. 管理员在导入列表的“待初审”中查看内容，点击单条“同意”或勾选后“同意所选”，稿件进入“待分配”。
2. 切换“待分配”，勾选稿件、选择启用中的团队成员，再点击“分配所选”。同一原帖只能有一个版本进入分配流程；已经发布的原帖修订仍由管理员直接审核。
3. 成员登录原团队后台，打开“分配给我的帖子”，填写价格、联系方式并修改内容；可“保存草稿”，资料完善后“提交审核”。
4. 提交后稿件锁定。管理员可在“合作帖子管理”卡片内直接终审，也可打开导入稿终审页。照片加载完成后点击“审核通过并发布”，无需额外勾选确认。
5. “退回修改”会保留文字和私有照片，并显示审核说明；成员修改后重提。发布后沿用原规则，仅管理员可修改公开内容。

新流程沿用团队固定发帖额度：初审、分配和保存不占额度；提交审核时占用一次，终审通过继续计入累计使用量，退回释放。重提更新同一条投稿记录并重新占用一次，不累加多条记录。历史使用量持续计入，剩余额度跨月保留，仅由管理员手动增加；详见 [团队固定发帖额度](team-post-quota.md)。

工作稿复用原导入字段和私有照片。成员仅能读取本人负责的稿件，图片通过团队路径鉴权访问，固定使用管理员保存的网址覆盖配置；初审、分配、保存和提交均不生成公开图片。终审发布复用原导入发布及去重逻辑，并登记成员归属。原普通投稿审核按钮不能绕过导入稿终审。删除成员账号时，未完成分配稿回到待分配，已发布稿保留内容并解除成员关联。

最简版不包含自动分配、通知、排名或额外统计；分配中的稿件不能从原批量删除入口移除。

新增迁移：`prisma/migrations/20260928000300_add_partner_import_assignments/migration.sql`，仅新增两个可空关联字段和两个索引，已有稿件保持原状态。启用真实环境前需明确授权程序自动加载现有配置、补齐这次结构并登记迁移；不需要读取帖子内容或执行全库迁移。专用命令为 `node scripts/apply-partner-assignment-schema.mjs --apply`，未经授权不要运行。

## 规则示例（虚构选择器）
```json
{
  "postLinkSelector": "main .post-card a.post-link",
  "fields": {
    "name": "article h1",
    "services": "article .content",
    "price": "article .price"
  },
  "photoSelector": "article .photos img"
}
```
字段支持 name、type、city、district、price、services、courseNotes、age、phone、wechat、qq、otherContact、address。
文本选择器精确匹配单个区域，图片匹配 img，列表链接匹配 a。
也支持 `data-import-field="services"` 等明确标记。
旧版本保存的默认链接规则会在读取时自动兼容标题内链接；自定义字段和图片规则保留。
任务保存配置快照；临时网络失败可重试旧任务，修改规则后应重新提交同页网址。
字段映射修复不会覆盖已保存草稿或人工编辑。若旧稿缺少标题下介绍或服务内容混入年龄、联系方式等信息，请重新建立同页任务，新提取结果会生成新的私有待审版本；核对后可批量删除旧稿。
已成功导入但图片不正确的条目不会由“重试失败条目”重新采集。修好规则并保存所需图片域名后，需重新建立同页任务，图片变化会生成新的私有待审版本。新稿的图片核对完成后，再手动拒绝或批量删除旧错图稿；旧稿及其人工编辑不会被自动删除或复制到新稿，已发布内容也不会被自动覆盖。
列表失败会区分连接、权限、文字编码、规则未匹配及链接被过滤；任务页按固定错误类型汇总失败数量，不回显原始异常。
下载器支持 gzip、deflate、Brotli，压缩前后均受大小限制，解压也受总超时限制。
不需要将真实 HTML、正文、图片或访问凭据交给 AI；调试可提供虚构的同结构模板。

## 数据与发布
- 导入数据单独保存在 PartnerImportSource / Job / Item / ImportedPost / Draft，与公开 Teacher 分离。
- 私有图片在 `storage/partner-import`；预览经过管理员认证且禁止缓存，发布时才复制到公开目录。
- 下载限制精确域名、HTTPS、公网 IP，固定 DNS 解析地址连接，每跳重验，限时限长；图片安全解码重编码。
- 按来源及最终详情 URL 去重，正文和图片摘要相同则跳过，包括已拒绝版本。
- 来源变化只生成新待审稿，绝不自动覆盖已发布内容。
- 审核保存校验稿件版本，发布还校验公开版本，阻止并发操作静默覆盖。
- 中断条目租约 10 分钟后可继续；已完成条目不受影响。
- 任务只显示数量和固定错误类型，不记录响应正文或真实错误堆栈。
- 私有审核副本默认保留，没有自动保留期清理；管理员可主动批量删除未发布草稿。删除前校验每条的状态和版本，任一已变更则整批停止；提交后清理对应私有照片。图片清理失败会返回固定提示，删除的草稿已无法访问，公开照片不受影响。
- 新入口与原来的“API 数据导入”独立。原 API 入口直接发布行为保持原样，合作网站请使用新入口。

## 本地中转到正式站

正式站访问合作方返回 403、而本地可正常导入时，可使用文件中转：

1. 本地后台完成列表页导入，保留草稿为待初审。
2. 打开本地导入任务，点击“下载中转文件”。仅导出该任务仍待初审的草稿及私有照片，最多 50 条。
3. 正式站导入管理页找到“上传本地中转文件”，选择与本地相同域名的来源，上传下载的 .jsonl 文件。来源编号不必相同。
4. 上传完成后到正式站待初审列表审核，再按原流程分配成员、修改和终审。上传本身不发布，不分配成员，不扣发帖额度。

浏览器逐条上传，并显示新增/跳过数量。重复上传同一版本会跳过，内容变化只增加待初审版本。中断后可以重新上传整个文件，已成功条目保留。首次中转与此前直接采集采用不同内容摘要，可能产生新的待审版本，请审核时核对。

中转文件包含帖子和照片，请妥善保管。下载结束标记用于检测文件截断；导出期间稿件变更会中止下载，需要重新导出。文件不包含账号密码、内部负责人或发布状态。每条最多 8 张照片、单图 5MB、照片合计 12MB，HTTP 请求最多 18MiB，反向代理上传限制需至少 20MiB。服务端重新校验字段并安全解码图片，仅写入私有草稿及存储。不会访问文件中的远程地址。

离线中转测试：`node --test scripts/partner-import-transfer.test.mjs`。真实帖子中转需管理员自行在本地与正式站完成，不由自动化验证读取或传输。
