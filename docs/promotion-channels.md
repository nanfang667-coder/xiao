# 推广短链渠道统计

后台入口：`/adminzhangzhang/channels`，后台首页及用户管理页均提供入口。

## 使用

1. 完成代码部署和数据库更新后，在“推广渠道”中创建渠道。例如名称 `GP77 推广`、短域名 `gp77.top`、渠道标识 `gp77`。
2. 复制该渠道显示的重定向地址。当前主站配置对应 `https://fenglou1.com/go/gp77`。
3. 在短域名的服务商、CDN 或 Web 服务器配置 HTTP 重定向（建议 302/307），让 `https://gp77.top/` 跳转到上面的完整地址。仅添加 DNS 解析不能完成 HTTP 重定向；域名及 HTTPS 证书仍由现有托管配置负责。
4. 从短链进入网站后，回到“推广渠道”刷新即可查看该渠道的统计。

### 已创建 GP77 渠道但访问仍为零

若 `gp77.top` 仍直接跳到主站首页，需要更新 Nginx 的旧重定向规则。后台创建渠道不会自动修改 Nginx。现有服务器可使用 `scripts/fix-gp77-redirect.py --apply`（Python 3、root），不需要重新构建或重启应用。

此工具只在 `/etc/nginx/sites-enabled/hulim` 中声明 GP77 的 server 块前加入根路径条件：`gp77.top/` 和 `www.gp77.top/` 的 HTTP/HTTPS 请求临时跳转到 `https://fenglou1.com/go/gp77`；其余域名及非根路径保留原规则。配置不符合预期或已包含补丁时停止。

修改前在 `/var/backups/hulim-nginx/gp77-before-*/hulim.conf` 保存原配置，原子写入后运行 `nginx -t` 并平滑重载；验证失败会恢复原配置。验证只使用不跟随跳转的 HEAD，请求不会进入计数入口。脚本不读取环境文件、数据库或业务日志，也不修改证书、应用发布版本或已安装的部署脚本。

完成后使用新的无痕窗口访问短域名，再刷新渠道后台；旧浏览器可能缓存此前的 301 首页跳转。同一浏览器重复进入主要增加访问次数，独立访客按匿名 Cookie 去重。

每个渠道的标识创建后固定。可修改显示名称和短域名标签；修改标签不会自动修改域名服务商的配置。另一个独立推广入口应新建渠道，以便分别统计。停用后仍跳转到主站首页，但停止记录渠道访问；恢复启用后继续沿用历史统计。

## 统计口径

- **今日新增访客**：北京时间当天首次访问该渠道的浏览器。老访客今天回来不算新增。
- **近24小时访客**：过去24小时访问过该渠道的浏览器，包括老访客。
- **累计独立访客**：同一浏览器在同一渠道只占一条记录。
- **访问次数**：累计通过该渠道入口进入的 GET 请求次数，包含重复打开。HEAD 和带预取标识的请求不计数。

这些是浏览器访问统计，不是实名人数或注册人数。更换设备、清除 Cookie、拒绝 Cookie 或自动化访问会影响数字。不同渠道可以包含同一浏览器，不能将各渠道独立访客直接相加当作全站独立访客。

匿名 ID 在统一主站域名上读取或创建，复用现有访客 Cookie。数据库仅保存带渠道命名空间的哈希，不新增 IP、原始 Cookie 或设备指纹。推广渠道不写入 `ref_code`、`User.referredBy` 或 `siteId`，也不把渠道访问写入邀请码统计。全站访问仍由现有首页访客统计记录。

短域名标签仅用于后台管理，不参与跳转目标拼接，也不根据浏览器 Referer 判断来源。公开的 `/go/标识` 入口本身就是渠道链接，直接分享该入口也会计入该渠道。需要同时统计不同投放位置时，应使用不同渠道标识。

## 部署

本次新增迁移：`prisma/migrations/20261011000100_add_promotion_channels/migration.sql`。

迁移仅创建 `PromotionChannel`、`PromotionChannelVisit` 及相关索引，不修改现有用户、站点或邀请数据。应在现有部署流程中应用经过审核的待执行迁移，并用更新后的 `prisma/schema.prisma` 重新生成 Prisma Client，再启动新版本。请勿为此重置现有数据库。

此次开发没有访问或更新线上数据库，没有配置 gp77.top 的 DNS、证书或重定向，也没有预先创建真实渠道。若数据库未更新，后台会提示先完成部署，公开渠道入口在统计存储异常时仍会跳转首页。
